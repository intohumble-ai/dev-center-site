여러 봇을 동시에 만들다 보면 무엇을 어디까지 했는지 잊고 끝맺지 못한 채 다른 일로 넘어가는 일이 잦았다. 그래서 GitHub·LinkedIn 처럼 개발 이력이 전부 쌓이는 자리를 만들었다. PC 의 빌더가 10분마다 각 봇의 상태(서비스 가동·로그 신선도)와 아이디어 큐·활동 기록을 읽어 정적 사이트로 빌드하고, 비밀 스캐너(정규식 + .env 값 대조)를 통과한 경우에만 공개 저장소에 올린다. PC 가 꺼져도 마지막 스냅샷이 남는다. 이 부분은 지금 가동 중이다. 아이디어 큐 자동구현 엔진은 소유자 전용 텔레그램으로 들어온 아이디어를 별도 워크트리에서 구현 → 테스트 → 콜드 감사 → 배포 금지시간 회피 → 배포 → 헬스체크(실패 시 롤백)까지 처리하도록 만들었고, 실가동 1건(삼국지 게임의 상태 요약 함수)을 구현·테스트·감사·배포까지 성공시켰다. 그러나 실돈 봇까지 자동 배포하기에는 콜드 감사가 3연속 FAIL — 변조를 사후 흔적으로 탐지하는 방식은 우회 경로가 계속 나왔다. 그래서 자동 구현은 일시정지하고 샌드박스 격리 방식으로 재설계 중이다. 큐는 쌓이지만 사람이 풀어줄 때까지 돌지 않는다.

새 창에서 열기 →
  1. 공개 페이지에 익명 입력창을 두면 "출금해라" 같은 문장이 자동 배포 경로로 들어갈 수 있어 입력 경로를 본인 전용 텔레그램으로 못 박았다
  2. 엔진 첫 실가동은 워크트리의 .venv/node_modules 심볼릭 링크가 그대로 커밋되는 버그로 실패했다 → info/exclude 등록 + 커밋 위생 관문(미커밋·의존성·심볼릭 링크 검사)을 추가했다
  3. 콜드 감사 1차에서 프로젝트 설명이 그대로 HTML 에 들어가는 XSS 가 잡혔다 — 내 YAML 만 들어온다고 가정했지만 자동 등록 초안은 폴더명을 그대로 쓰므로 이스케이프를 전부 넣었다
  4. 발행 스크립트가 upstream 없는 브랜치에서 push 성공 판정을 못 해 매 주기 다시 push 하던 것을 origin/<branch> 기준 판정으로 고쳤고, 공개 저장소에 쌓인 초기 이력은 리셋 스크립트로 정리했다(복귀 로직·테스트 포함)
  5. 엔진 감사는 FAIL 8건 → 재감사 FAIL(무시파일 우회·훅 무력화) → 3차 FAIL 로 이어졌다. 변조를 사후 흔적(지문·git 메타)으로 잡는 방식은 우회가 계속 나와 한계를 인정하고, 샌드박스에서 격리 실행하는 방식으로 재설계하기로 했다
  6. 비밀 스캐너는 처음엔 시간 단위·수량·통화까지 가려 과마스킹이 심했다 — 화이트리스트와 변형(쉼표 금액·전화 변형) 테스트를 쌓아 "가릴 것은 가리고 읽을 수 있게"를 맞췄다
  7. butler 봇 토큰은 다른 봇이 이미 폴링 중이라 수신용으로 못 쓴다 — 전용 봇 토큰이 필요했다
